The gap is in the tap-verify loop decision. `tapcal.py
verify` could not tell "the tap missed the target" from "the
tap hit the target and the game ignored it": every unchanged
tap was a miss, and the loop answered retry with a next aim
shifted by the landing error - zero for an on-target tap. The
fix names that shape instead of retrying it:

- Per-attempt verdict "ignored": tap landed exactly on the
  target (miss 0,0) and the state did not change.
- Loop verdict "input-blocked" when the last attempt is
  ignored: no next aim; the text form names the recovery
  (re-front the app via Dock icon / mac_lastwar_front.sh,
  then re-probe; do not retry the same aim). It outranks the
  count-based exhausted verdict so the cause is never hidden
  behind a retry count.
- Docstring records the #575 fullscreen measurement (offset
  about +70 right, -14 up; a compensated tap worked), so a
  fullscreen offset is real and compensable through
  calibrate/compensate - input-blocked is a separate failure
  from geometry.
- tapcal 1.2.0 -> 1.3.0; _tools_/INDEX.md tapcal row updated.
