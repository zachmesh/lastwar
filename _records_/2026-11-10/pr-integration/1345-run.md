## Correction - malformed action-log line in the run-record commit

- The run-record commit d7e0cd677 carried a malformed
  action-log line: its line 1554 held two JSON objects
  concatenated (the pr-catchall 1339 line plus this
  run's line). Root cause: the 1339 line had no
  trailing newline, so the append landed on the same
  line. The pre-commit log_append.py check did report
  "1 of 1554 lines do not parse as JSON", but the
  commit went ahead because the check ran through a
  pipe to tail, which masked its non-zero exit code
  under set -e.
- Repaired in the follow-up commit carrying this
  correction: line 1554 was split into two lines with
  bytes preserved (raw split via JSONDecoder, object
  multiset verified unchanged), a repair action-log
  line was appended, and log_append.py check was
  re-run with its exit code captured directly - it
  reports clean. Lesson for later passes: never pipe
  the log check through tail; capture the exit code
  first.
