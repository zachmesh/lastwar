# Lessons

- Stacked landing: merge the base PR first. The stacked head is then one commit behind main, but main's tree equals its parent's tree, so the merge tree equals the branch tree.
- Privacy before the redaction lands: a branch on a base that still carries the identifier cannot read 0 for the whole tree. Judge the added matches per changed file, line, wrapped form and diff line, and prove the check with a deliberately adding commit. The positive control must use a revision known to carry the identifier (control --rev).
- The hand-off said 171 redaction-only files; verify-diff proved 166. The rest were 4 index splits and 1 decision-register entry also edited in place. Count what the tool proves.
- check --base has no redaction exemption (94 findings on PR 874, all on redaction-only files); check --staged replayed on the merge-base is the verdict.
- A branch built on the old local line is never pushed as built (73 commits, 165 files with a match). Cherry-pick its commit onto main; evidence of a mechanical rebase is blob identity (4 of 5 files) plus a one-line explained difference.
- cu-bridge tests ran only after claimed held no unit (10 OK in 21 s, no leftovers).
- Main after all three merges: whole tree 0 on every count; inherited metadata 1, unchanged. The scan prototype is now sha1 6a0a679ef890, 349 lines.
