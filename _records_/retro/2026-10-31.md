## Scope, snapshot and method

- Pool snapshot - `_queue_/done` as read 2026-11-01T05:24Z,
  428 units, all with a result block. Inbox (52) and claimed (0)
  at the same read are ticker state, not retro data, and are
  not committed by this run.
- Window - the task asks for the past 7 days, local
  2026-10-25 to 2026-10-31. Unit-structured data exists only
  for local 2026-10-28 to 2026-10-31, because the queue cut
  over on 2026-10-28. Local 2026-10-25 to 2026-10-27 are
  pre-queue segment records (88, 137 and 116 files) and are
  not unit-comparable, so they are excluded from the per-type
  table rather than forced into it. The window below is
  therefore 4 days of unit data, stated plainly, not 7.
- Dates below are local PDT dates derived from each unit
  finished_at in UTC minus 7 hours. Per local day - Oct 28
  111 units, Oct 29 117, Oct 30 116, Oct 31 84.
- Parser - aggregation used the queue tool own tolerant
  frontmatter parser, which splits each line on its first
  colon. A strict YAML parse of the same 428 frontmatters
  fails on 100 files (23 percent), because unit summaries
  carry unquoted colons. Any strict YAML consumer of this
  pool silently drops nearly a quarter of the units. That
  fragility is itself a finding, action M3 below.
- No retro tool exists yet - `tools/retro_report.py` is
  specified in design section 14 but not implemented, so this
  retro aggregates directly per the specification. The tool
  remains unbuilt; this file does not claim otherwise.

  retro purposes, because all 428 lack the required keys -
  0 carry blocker_category, 0 carry verified, 0 carry
