# `_records_/retro/`

The standing cross-day series of the retro review mechanism,
beside the date folders of `_records_`, as registered in the
task unit queue design (section 14). One day retro looks back
over the past 7 days; this folder is where its evidence and
its judgement live.

## Contents by file shape

- `<date>.md` - the daily retro file for that local date,
  written by the retro pass. The per-type reading, the largest
  loss points, and the improvement actions split into execution
  knowledge and meta knowledge, each with its verification
  method and next-day recheck.
- `<date>-data.json` and `<date>-data.md` - the metrics
  appendix for the window ending on that date, generated by
  `_tools_/retro_report.py` from the unit results in
  `_queue_/done`. The JSON is canonical; the Markdown renders
  the same numbers as tables for the retro file to cite.
- `rolling-7d.md` - the standing rolling metrics series the
  retro pass maintains across days.

## Derived artifacts

The data appendices are derived artifacts under constitution
C1 - regenerated from the unit results, which remain the
immutable source. A regenerated appendix states the pool state
it was derived from (the scanned unit count and a hash over
the scanned units), so a reader can tell whether the pool
moved between runs. Re-running the tool over the same window
and the same pool overwrites the appendix with identical
content; it never appends a second copy.
