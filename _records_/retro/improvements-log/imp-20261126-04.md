### IMP-20261126-04 - a leftover test server listens on every interface

- source: Steer A's note of 17:22Z; the Scribe's read of the process at 17:23Z (by pid; names only, no contents).
- class: tool safety
- leak: a Python web server, `python -m http.server 8765` (pid 82894), left by the bridge's 11-22 browser-mode test, had listened on every interface (`*:8765`) for 85 h 56 min at 17:23Z, serving `/tmp/cu-test` (index.html, server.log). Steer A says it held nothing private; contents not read here.
- root cause: a one-off test server had no owner, no stop time and no place in any list, and no routine looks at listening ports.
- fix: (a) the Coordinator asks the [cu] Coordinator in one line whether any test still needs port 8765; with no answer of 'needed' in 15 minutes the operator or the Toolsmith's tcc-who step stops it: read `ps -o pid,ppid,etime,command -p 82894`, confirm it still names `http.server 8765`, kill once with no -9, and record pid, elapsed, port and the folder's name; (b) the weekly health read gains a listening-port list, names and ports only (process, port, elapsed); (c) one line for the owner's digest, Steer A's: 'a Python web server on port 8765, left by the 11-22 bridge test, listened on every interface for 85 hours: the team stopped it: the page held nothing private'.
- target metric and current value: (1) listening ports not on the team's named list, baseline 1 (8765) on 11-26; (2) hours a test server outlives its test, baseline 85.9 (n = 1); (3) health reads with the port list, baseline 0.
- verification: the weekly health read carries the port list. It closes when (1) is 0 on the first two weekly reads after the stop and the stop is recorded.
- status: open - the process was still running at 17:23Z; the stop waits for the [cu] answer.
