### IMP-20261123-07 - a bridge restart leaves an orphan daemon and a stuck run

- source: run `20261123T063411Z-49accf` of 2026-11-23 06:34Z, found by the
  Steward and the coordinator at 06:40Z; record
  `_records_/2026-11-22/team-operations/2240-account-elsewhere.md`.
- class: tool
- leak: the operator restarted the bridge at about 06:37Z while the run was
  waiting on a consent request for another app (the owner's browser). The old
  daemon stayed alive for 3 hours 5 minutes with the run in `awaiting_consent`,
  while `status` and `control stop` reached only the new daemon and answered
  "no run in this server". The run could not be stopped with the sanctioned
  commands, and an approval of that consent prompt would have let it drive the
  owner's browser. The coordinator ended it by terminating the orphan daemon
  and its child at 06:41Z.
- target metric: orphan `cu_bridge serve` processes after any restart, target
  0; runs that `stop` cannot reach, target 0.
- verification: a test that starts a run, restarts the daemon, and shows
  `status` and `control stop` still reach the run or the old daemon is ended;
  `status` lists every daemon it can see.
- status: open - assigned to the toolsmith after the privacy redaction tool.
