## Diagnosis (issue 235)

The schedule was not stale; the clock was wrong.
duel_schedule.json declares timezone America/Los_Angeles
and a 19:00 local anchor, but duel.py used naive
datetime.now(). On a UTC host that rolls to the next duel
day at 11:00 PT, eight hours early. The reported instant,
2026-11-03 14:03 PT, is 22:03 UTC, so the old code read
Day 3 (Age of Science, release) while the live game,
correctly on Day 2 (Base Expansion, stack), said radar
tasks score nothing today. The corrected tool returns
Day 2, stack, gate do NOT claim, for that instant,
matching the live dialog verbatim, so no schedule edit
is owed.
