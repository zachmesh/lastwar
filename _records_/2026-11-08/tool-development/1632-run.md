## Work done

Issue #465 - two defects, both in `_tools_/queue.py`:

Defect 1 - plan re-stages marker-closed fixed-slot units: the
1340 planner run dropped the stale inbox copies of
training/donations/arms-race-2026-11-08-1003 via
`_drop_done_duplicates`, then in the same run re-staged fresh
units for the same (regular, slot), because `cmd_plan` consulted
neither completion markers nor branch done records and
`_produce_for_window` was called without `closed_ids`.

Defect 2 - sync expiry races branch reconciliation: in
`cmd_sync`, `_expire_stale` ran BEFORE the branch fetch, and it
consulted only the live pool done dir and markers - not the
branch. A unit whose true done record lives only on the branch
would have taken a bogus local `expired` record at its expiry
instant, conflicting with the branch's true record.

Fix (commit 49ce4575, branch work/plan-branch-closed-slots):
- `cmd_plan` fetches today's delivered records branch first,
  drops branch-done inbox copies, and passes the closed set
  (branch done ids + live completion markers) into
  `_produce_for_window` via `closed_ids` - the hook #466 left
  for this. A closed slot is not staged and is reported in the
  plan JSON as `skipped_closed`; the plan JSON also gains
  `branch_done_reconciled` / `branch_done_reconcile_warning`.
  A branch that cannot be read warns and the run continues on
  local state only.
- `cmd_sync` fetches the branch done set BEFORE `_expire_stale`,
  and `_expire_stale` takes an optional `branch_done` set: a
  stale inbox copy whose unit is branch-done is dropped with a
  stderr warning instead of taking a bogus expiry. `cmd_plan`
  passes the same set. Callers that pass no set (`cmd_reap`,
  `cmd_sweep` via `_produce_for_window` without `closed_ids`)
  keep the old behaviour.
- `_tools_/INDEX.md`: queue.py row mentions the plan guard and
  the expiry guard.
