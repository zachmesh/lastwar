## Work done

Issue #466 - ticker-1352 ran `tools/queue.py sync` and the sync
produced a fresh unit radar-2026-11-08-1003 for a slot ticker-1249
had already closed, its done file already on records/2026-11-08.
Root cause: PR #448 made sync drop inbox copies already done on
the delivered branch, but step-3 production in
`_produce_for_window` dedupes only on the live pool - so the same
tick minted a fresh unit with the same deterministic id right
after the drop.

Fix (commit 1b0221bcc, branch work/sync-produce-branch-done):
- `_tools_/queue.py`: sync production consults the closed set
  before minting - the branch done set from step 1 plus live
  completion markers (new `completion_marker_units`, same
  validity rule as `has_completion_marker`). A closed slot is
  skipped, reported in the sync JSON as `skipped_closed`, and a
  stderr warning names the unit and where it closed.
- `_produce_for_window` takes an optional `closed_ids`
  (unit -> where it closed); the check runs after the live-pool
  scan so the stale-geometry warning (#410) still fires first.
  The unit id formula is factored into `_unit_id_for_window`,
  one formula for the guard and the reporting. Callers that
  pass no closed set keep the old behaviour; plan wires its
  own set under #465, sweep is untouched.
- `_tools_/INDEX.md`: queue.py row mentions the guard.
