## Correction - the 1851 pass clean claim does not hold

The 1851 run record claimed all five records branches
test-merge CLEAN against main 8911598e84 by merge-tree,
"so the four GitHub CONFLICTING flags look stale", and
its day-INDEX section repeats the claim. That claim is
contradicted by this pass's re-verification with the
correct merge-tree form against the same main
8911598e84: PR 334 rc 0 clean, but PRs 324, 301, 265
and 256 all rc 1 with a content conflict on
_logs_/repo-actions/action-log.jsonl. The flags are not
stale. The trap is the merge-tree call form: on git
2.43.0, `git merge-tree --write-tree <base> <ours>
<theirs>` is a usage error (rc 129, three positional
trees are not accepted outside --trivial-merge); the
base must be passed as --merge-base=<commit>. This
pass's first merge-tree attempt hit exactly that
rc 129 usage error, and every verdict in this record
uses the corrected --merge-base form with the exit
code checked. The retro should treat the 1851 "all
clean" line as an error, not as evidence, and should
note the same form trap that the 1500 pass already
flagged in the 1445 record.
