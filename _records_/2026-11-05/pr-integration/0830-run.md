## Push correction

The first push of this record went nowhere: the pass had
checked out github/records/2026-11-05 in detached HEAD
state, committed 580fd041 there, and then pushed the
local branch records/2026-11-05, which was still at the
old tip e515b340 - so the remote stayed at e515b340 and
the commit sat stranded on detached HEAD. Caught by
ls-remote showing the old head after PUSH-OK. Fixed by
pushing the explicit SHA (580fd041:records/2026-11-05);
remote verified at 580fd041 after the fix. The local
branch was then fast-forwarded to the remote tip, so
future passes checking out records/2026-11-05 land on
the current head instead of a stale local branch.
Lesson: always push the branch by explicit SHA or from
a checked-out local branch, and always re-read ls-remote
after push - a PUSH-OK line alone does not prove the
remote moved.
