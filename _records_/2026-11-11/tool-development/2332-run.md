Implemented in PR #683 (branch work/sweep-roster-freshness-606,
commit 3d1e5b707): a roster-freshness gate in `_tools_/queue.py`.
Before `plan` or `sweep` stages anything for a reset-anchored
regular, it compares this copy's `slots_before_reset_minutes`
against main's roster (fetched into a private ref, same pattern
as the branch reconcile). A readable main whose offsets differ is
positive proof the staging copy is stale, so the regular is
refused outright - `plan` exits 1 with the refusal in its JSON
output, `sweep` exits 1 - instead of minting a wrong-geometry
pair. The refusal happens before any fix-up is staged, so a
refused sweep leaves no orphan fix-ups at the old midpoint for
the corrected re-run to duplicate. `_produce_for_window` keeps
the same check as a backstop for any caller that stages without
pre-checking. An unreadable main (no git remote, fetch failed)
warns once and stages from the local roster - fail-open, like
the branch reconcile. `_tools_/INDEX.md` queue.py row updated.
Progress and the implementing PR commented on issue #606
(issuecomment-6817864854).
