## What changed

- `_tools_/queue.py` resolve_pool_root(): prefers the
  _queue_/ subdir whenever it exists, so a repository root
  holding both a stray top-level pool and a _queue_/ subdir
  resolves to the real pool. A root with only top-level state
  directories still passes through as a pool, and an empty
  root still passes through for the caller to judge; the
  reorder is behaviour-preserving except for the both-present
  case. Docstring updated.
- `_tools_/queue.py` pool_root_warning(): when the resolved
  pool is a _queue_ directory whose parent still holds
  top-level state directories, returns a warning naming the
  stray (which state dirs, at which path) so it gets removed
  instead of silently ignored. Warn-only, never a block.
- `_tools_/queue.py` cmd_enqueue(): prints the
  pool_root_warning, so the stray is named on the write path
  too; the #510 refusal for a root with no pool state
  directory is unchanged.
- `_tools_/scout_diff.py` main(): prints the pool_root_warning
  on --apply as well as on dry runs (previously dry-run only),
  so a stray beside the resolved pool is named on the write
  path; the --apply refusal for a root with no pool state
  directory is unchanged.
- `_tools_/INDEX.md`: queue.py and scout_diff.py rows document
  the new behaviour (issue #539).
