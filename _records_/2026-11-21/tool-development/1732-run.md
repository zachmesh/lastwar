already_present count disagreed with the pool by 1 in two
consecutive runs (1740: tool 67 vs post-expiry pre-stage pool

landed in the repo (records PR #762 covers only through the
1540 run), so the proximate trigger of those two runs is not
recoverable from the landed records. The defect class is proven
on current code: `_produce_for_window` returns None for a
refusal (expired window, duplicate chain step, stale roster)
as well as for a genuine dedupe hit, and plan's else branch
counted every unproduced, unclosed window as present. The
expired refusal was already classified into skipped_expired by
R15; the chain-seq and roster refusals fell through and were
counted as present. The fix classifies every unproduced window
before counting it - expired into skipped_expired, duplicate
chain step into new skipped_chain_seq, stale roster into new
skipped_roster_refusals - and only a genuine (regular,
planned_for) dedupe hit increments already_present. The same
rule is applied in the pre-reset fix-up staging (whose refused
fix-ups are reported the same way) and in sweep's pair loop;
the roster-freshness refusal now carries the refused window's
unit id so callers can classify it. Design doc gains rule R19
(changelog 0.27.0); the queue.py INDEX row gains the #744
sentence.
