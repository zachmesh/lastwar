Issue #800 (filed by the daily retro 2026-11-21): the
structured coverage file for 2026-11-21 reports unexplained
red dots 0, but the pass narratives name unexplained badges -
ticker-2004 (10 seen, 9 explained, 1 unexplained, red target
icon badge) and ticker-1604 (Black Market exclamation badge
and Desert Battlefield New badge). The coverage file itself
notes no red-dot accounting section was found. The day's
count is ruled 1 by the latest pass narrative (ticker-2004).
Reproduced on the main tool against the real observation:
unexplained 0, basis empty, "No red-dot accounting section
was found". The four Coverage sections in the file state
23/23/0 (1604), 8/8/0 (1704), 7/6/1 (1904, the 99+ chest
badge), 6/6/0 (1934) - but as prose, two of them embedded
mid-bullet in the Surfaces-walked bullet, so the parser saw
none of them.

The fix (commit c9eb916fb, branch
work/scout-coverage-800-prose, base main 5a3baa615): a
`Coverage` / `Coverage update (...)` heading starts a prose
accounting section; every bullet in it is held until its
wrapped lines have all been read and then searched for the
`Red dots seen ...` statement, anywhere in the bullet. The
numbers must add up (seen = explained + unexplained) or the
section reads as unstated; the parenthetical after the
unexplained count names the dots. Bullet accounting lines
are never read inside a prose section, and a level-3 sub-read
heading does not end it. The first version of the fix only
matched bullets starting with the statement and caught just
the 1604 section (the 1704/1904/1934 statements sit
mid-bullet); the embedded form was found by the end-to-end
run and the fix was generalised before committing.
