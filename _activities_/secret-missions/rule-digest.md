# Rule digest

1. The post's base-column slot rotates; verify the title SECRET COMMAND POST before any tap (how-to-enter-p1).
2. Claim soon after the shortest tasks finish: one Claim tap collected all finished tasks, and tasks left unclaimed for hours get plundered (how-claiming-works-p1, run-20261122-1104-p1).
3. If Claim does nothing, change method each unit; a 2nd consecutive failure files a GitHub Issue, a 3rd writes the blocker into metadata (how-claiming-works-p2, run-20261122-0244-p2).
4. Dispatch with Mega Deploy by default; its toast "no tasks available for dispatch" is the nothing-pending check; on scoring duel days Mega Refresh first, cost unobserved so check it (how-it-is, day-20261122-p2, limits-section).
5. Red lines: no diamond or item spend; Plunder Others is PvP, never tapped (limits-section; OD-20261123-03, open, _records_/retro/owner-decisions-log/od-20261123-01.md).
6. Assist Allies caps at 5 per day; re-ground the Assist button per tab and row (ally-assists, _records_/2026-11-02/secret-missions/0426-queue-run.md).
7. The orange icon on a resolved task is a plunder stamp, not a dispatch panel (day-20261122-p1).
8. Check Reward Recovery whenever the post is open (reward-recovery).
9. Different-device dialog: the articles record one Confirm, then reopening the game (_records_/2026-11-03/secret-missions/0005-queue-run.md).

Unverified: tap methods, from old ticker units, not the current bridge (how-to-enter-p1); Mega Deploy centre, toast and orange-icon reading, from an issue whose source record is in no ref (how-it-is, day-20261122-p1); Mega Refresh cost (limits-section); any share of plundered rewards arriving (open-questions-p5).
