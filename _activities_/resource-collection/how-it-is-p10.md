Filed as tooling Issue #822.) (2026-11-22 1704 update: the MY PROFILE panel is a separate-surface case - it lives on window 127250 (642x919, accessibility=false) covering the base window 127196; taps sent while 127196 is selected pass through to the base underneath, so the panel surface must be activated by surface_id before any tap reaches it; even after activation its X does not close on coordinate taps (four taps: 896,50 exact-pointer, grounded 834,54, centre 880,52 - press-highlight only, 7-12% changed area, no close), the dimmed-area tap at 50,500 does nothing, and a swipe-back drag is unsupported on the screenshot-only surface ('can't send drag to it... Use click at a point of its image'). The X-tap close method is now a repeated failure (ticker-1634 element-number clicks gave a 'Google Chrome came to the front' artifact, this unit four coordinate taps) - filed as tooling Issue #854. R2: the next unit of any type that finds the Profile panel open must arrive with a changed close method (double-tap on the X, long-press, or relaunching the game so the panel is not open at session start); a third consecutive unit blocked the same way is a process failure to report to the owner. Caution: window numbers are session-scoped - in the 1133 session 127250 was the DEAD duplicate window, in this session it is the LIVE panel surface; the live surface is the one holding the panel / keyboard focus, never a bare number.)
