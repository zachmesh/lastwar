# Rule digest

1. Ground the radar dish fresh every unit; the slot rotates and can open another screen (how-to-enter-p1, how-to-enter-p6).
2. Verify the radar screen before any work; if another opens, back out untouched; one unit, one type (how-to-enter-p8).
3. Follow the live duel day, not the window label: stack on even days, release on odd days 1, 3 and 5 (scoring-duel-days-p1, scoring-duel-days-p3).
4. Quick Execute covers ordinary tasks, never map pins; read the one offer the bar shows (quick-execute-coverage-p1).
5. Stack day: never tap Claim All or pins; record the pin inventory (map-pins-taxonomy-p2, day-20261122-p1).
6. Release day: work every pin to a closing read; unattempted pins make a partial (map-pins-taxonomy-p2).
7. No pin scan, no done (map-pins-taxonomy-p2).
8. A stack unit is done only with entry verified, every executable task run, closing reads taken and a Claim All-only bar named as the blocker (stack-day-completion).
9. Stamina: free claim first, then items, never rubies; buying 100 for 300 rubies is a red line (stamina-section).
10. Radar points are not duel score (scoring-duel-days-p1).

Unverified: move-wait-click, normalized-coordinate and exact-pointer methods, measured by ticker units, not the current bridge (how-to-enter-p3, how-to-enter-p5, how-to-enter-p7); what selects the Quick Execute offer (quick-execute-coverage-p1); the stamina cap (stamina-section).
